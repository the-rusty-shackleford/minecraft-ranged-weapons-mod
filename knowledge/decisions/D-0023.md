# D-0023: The server chooses magazines or loose rounds; loose reaches into bags

Rusty, 2026-09-23: "Make 'requires magazines' a mode for the mod, and make another
mode that just pulls bullets from anywhere in your inventory at all (including
backpacks). Raise all ranged weapon mod bullet/round max stack sizes to 128." The
five calls in the preview were acked as recommended.

Accepted:

- One server config value, `ammunition.feed`, `MAGAZINES` (the default: D-0013 as it
  stands) or `LOOSE`, in the world's `serverconfig/rangedweaponsmod-server.toml`. A
  server config because the rule is the server's for everyone and NeoForge sends it
  to each client at login (`ConfigSync`), so the counter and tooltips show the rule
  in force. `FeedMode` is a domain enum; `GunItem.usesMagazines(stack, mode)` is
  the one question the gunnery, the HUD and the tooltip ask.
- Under `LOOSE` every gun is an internal store: the magazine-fed guns take the
  tube's path (`AmmoChoice` for the kind, `ReloadPlan.roundsToLoad` for the count)
  with the profile's capacity, which `MagazineFedWeapon` already reports with no
  magazine in. The load takes the gun's `magazine_change_ticks`: one handful, the
  number the player already knows, not a tick a round (which made the box 75; the
  D-0013 follow-up had already rejected that once). A gun holding a magazine hands
  it back on first sight, load and all (`Magazines.handBack`, the mirror of
  `adopt`); magazines stay craftable and fillable so nothing is lost.
- Reach. `domain.Pockets` is the pure value: a row of pockets, each a row of
  stacks; kinds in the order first met, counts, and a draw plan first pocket first,
  first stack first. `RoundSources` builds it from the player: the inventory as
  pocket 0 (hotbar first, as before), then in loose mode with Backpacks+ present
  the worn bag and the bags carried in slots, storage cells only, mounts never
  (they are gear). Rounds are drawn pockets before bags, so the bag is the
  reserve; rounds a swap hands back go to the inventory, never into a bag. The bag
  pocket goes through Backpacks+'s own public API as it stands in 0.2.1
  (`BagLocations.worn/stack/changed`, `BagContents.copy/store`): `store` refuses
  anything but a withdrawal and advances the bag's revision, so a bag menu bound to
  the old revision invalidates itself as Backpacks+ intends. Backpacks+ needs no
  change and stays optional; it is on the gametest classpath only so the bag
  pocket is proven against the real thing.
- Bag reach only in loose mode: in magazines mode the shotgun, revolver and the
  Fill button see the inventory alone, as before. The two modes differ in exactly
  two things, as asked.
- Rounds stack to 99, not 128: the game's max-stack-size component accepts
  1..99 (`DataComponents.MAX_STACK_SIZE`), a saved stack's count is validated in
  the same range (`ItemStack.CODEC`), and `Item.ABSOLUTE_MAX_STACK_SIZE` is 99, so a
  stack of 128 would be refused when the world loads and vanish. Going past 99
  means mixins into vanilla's item codecs and every container's slot cap; not done.
- The mod's package is `com.chunkworks.rangedweaponsmod` from this version (Rusty:
  "there should be no com.nfx anywhere"). The protocol library stays
  `com.nfx.rangedweapons` until it and its consumers (Armed Pillagers, the AGM
  bridge) move together.

Rejected: a common config (not synced; the client's HUD would guess); a gamerule
(not what was asked, and NeoForge configs are the idiom); reach as a separate
switch (four combinations nobody asked for; the keys are additive if ever wanted);
unloading a handed-back magazine into loose rounds (more moving parts, and the
screen already unloads one); per-round loose reload times; counting mount cells.

Verified by `PocketsTest`, `FeedModeTest` and the loose-mode gametests named in the
2.7.0 verification record.
