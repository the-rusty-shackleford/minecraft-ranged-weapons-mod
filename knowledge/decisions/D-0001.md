# D-0001 — The protocol's fallback tier operates our guns

**Decision**: This mod implements no `RangedWeapon`. A gun is a plain
`GunItem` with a profile in the protocol's `rangedweapons:weapons` data map;
`RangedWeapons.resolve(stack)` yields the protocol's `ProfiledWeapon`, which
keeps the rounds in the protocol's component and fires the protocol's
`ProfiledBullet`. This mod adds only what is about a player holding the gun:
the trigger, the clock, the reload, the recoil, the counter, and a second
small data map (`rangedweaponsmod:handling`) for how it feels.

**Why**: The fallback tier was already a working weapon for mobs, proven on
the shared server through Armed Pillagers. Writing a second weapon
implementation here would have duplicated it, and any gun this mod fired
natively would then have had two behaviours: one when a player held it and
one when a mob did. On the fallback tier the same object serves both, so
every gun this mod ships is a gun any protocol consumer can arm a mob with on
the day it exists, and the next gun is a profile, a handling entry, a model
and sounds.

**Alternatives rejected**: *A native `RangedWeapon` per gun with a bridge for
mobs* — the bridge would expose exactly the profile the data map already
holds. *Per-stack stat overrides (attachments, wear) now* — nothing needs them
yet; when something does, a capability decorator over the profiled weapon
takes precedence in `resolve` without touching this decision.

**Follow-ups**: Ammo families as item tags in the profile's `ammo` field, so
a weapon can accept any of a family, belong in the protocol, not here.
