# D-0004 — The art is generated, and its display transforms were calibrated by photograph

**Decision**: Every asset -- the 32x32 texture atlas, the eighteen-element
voxel model, the round icon, five sounds -- is written by
`devtools/art/build.py` (Python, run with `uv run`), and the generated files
are committed beside it. The item model's display transforms were not
reasoned out: the gametest mod registers an axes model (red +X, green +Y,
yellow +Z) under candidate rotations, and `./gradlew runPhotoBooth` (a dev
client that quick-plays the gametest world, poses each item, screenshots and
quits) photographs them so the right one is read off the picture.

**Why**: The mod this replaces is all-rights-reserved, and its art was the
only reference at hand. Generating from code guarantees nothing is copied and
makes every asset reproducible and reviewable as a diff. The transforms
needed calibration because Minecraft's item display frames are not
documented: first person turned out to want a Y rotation of 90 to point +X
downrange, while the third-person arm frame is turned so that it is a Z
rotation of 90 that points +X forward with the gun upright -- neither
guessable, both visible in one booth run. The booth also caught two bugs
before the server did: the fallback bullet crashed on save (protocol 1.2.1),
and a gametest that had passed only because the mock player faced south.

**Alternatives rejected**: *Hand-drawn PNGs in an editor* — no editor on the
box, and not reviewable. *Reading the transforms from a vanilla model* —
vanilla's handheld items are a flat texture, a different frame from a voxel
gun. *A screenshot from the real client* — no windowing tools on the box,
and a dev client under script leaves no room for a human to nudge the frame.

**Follow-ups**: The calibration items live in the never-shipped gametest mod;
they cost nothing in the jar.
