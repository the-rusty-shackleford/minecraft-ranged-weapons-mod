# D-0006 — The click is offered to the target with vanilla's calls, then cancelled: vanilla's item use drops the hand

**Decision**: On the use key with a gun in the main hand, the client itself
offers the click to what is under the crosshair -- `interactAt` and
`interact` for an entity, `useItemOn` for a block, the same calls with the
same reach and packets vanilla's use path makes -- and then cancels the
event whether or not something took it. If nothing did, it sends this
mod's press. Vanilla's item-use step never runs for a gun. `GunItem.use`
stays as a working fallback for any client that does reach it.

**Why**: Vanilla's `startUseItem`, when an item's use consumes the click,
calls `ItemInHandRenderer.itemUsed`, which sets the hand height to zero:
the re-equip animation, the hand dropping out of view and rising back. It
does so on the press and on every four-tick repeat while the key is held.
D-0005 had put the press on that path to get interactions for free, and
what Rusty then felt for three builds as "the recoil kicks down" was this
animation, while three recoil rewrites changed nothing he could see. The
booth had not caught it because it fired by sending the trigger message
directly, never by pressing the key; it presses the key now.
Another Gun Mod escapes the same dip by returning pass on the client,
which also lets vanilla go on to use the off-hand item; offering the click
ourselves and cancelling keeps the off hand untouched.

**Alternatives rejected**: *Client returns pass* — the off-hand item gets
used (a torch placed) on every shot at a block in reach. *Reset the hand
height every tick behind vanilla's back* — an access transformer to undo
an animation vanilla is mid-way through, and it would also kill the real
equip animation. *Keep D-0005 and tune the kick* — done three times.
