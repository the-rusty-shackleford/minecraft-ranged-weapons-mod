# D-0016 — Read shared grip at pose time; synchronize aim through the existing engine

**Decision:** the client item extension reads the resolved weapon profile's grip
on each pose, with the former item grip only as the fallback for an old profile.
The pistol still obeys D-0015 and inputs still obey D-0011. A transient boolean
attachment, `ModData.AIMING`, carries accepted aim to the holder and trackers.
Only changes are written. NeoForge 21.1.248's attachment synchronization sends
both initial state and updates; `GUNNERY` and its private clocks remain server-only.
The server rejects unarmed/dead/spectator aim and clears it when the weapon leaves.
The existing `RELOAD` item component remains the sole reload clock.

**Why:** Rusty's observer-sync request identified the lack of an outgoing aim
packet, but an extra packet is not necessary: the installed engine has attachment
sync. The reload component already declares a stream codec and reaches observers
through vanilla equipment synchronization. Duplicating it would create competing
clocks and cancellation paths. A held key is not saved or copied into a respawn.

**Evidence:** two server regressions reproduced unarmed aim acceptance and stale
aim after switching away before the fix. `ObserverBooth` exercises real entity
tracking, equipment packets and attachment handlers with one rendering client
and a server-controlled player as stimulus. It checks initial state, subsequent
changes, actual reload start/completion, weapon removal and local aim key edges.
The actor is not an independently connected client; that limit is explicit.

**Rejected:** synchronizing all of Gunnery; custom packets duplicating attachment
tracking; a second reload clock; changing the trigger-arm fingerprint or faking use.
