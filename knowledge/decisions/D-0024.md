# D-0024: The feed mode is each player's own, told to the server by their client

Rusty, 2026-09-24, told how the mode is switched (the world's server config, then a
restart): "It should be a per-player config setting."

Accepted:

- **The choice lives in the player's client config**, `ammunition.feed` in
  `config/rangedweaponsmod-client.toml`, `MAGAZINES` (the default) or `LOOSE`, with the
  same meanings as D-0023. NeoForge's own config screen is registered
  (`IConfigScreenFactory` → `ConfigurationScreen`), so it is also a page under Mods →
  Ranged Weapons Mod → Config, saved live; every other client value gets that page too.
- **The client tells the server**, with a `FeedPayload` (protocol "3"; a 2.7.x client is
  refused early rather than left guessing), at login (`ClientPlayerNetworkEvent.LoggingIn`)
  and whenever the client config reloads (`ModConfigEvent.Reloading` for that spec: the
  file edited, or the config page saved). `FeedSync.choose(mode)` sets, saves and tells,
  for the booth and any future key or command.
- **The server keeps it per connected player**, `FeedModes`, a map by UUID written on the
  server thread and dropped at logout; a player the server has not heard from is in
  `MAGAZINES`, the mode every gun is designed for. Nothing is persisted: the client says
  again at every login, and the client's file is the durable copy. The gunnery reads
  `FeedModes.of(player)`; the tooltip and the counter read the client's own setting
  (`FeedModes.local()`), so what a player sees changes the instant they change it, before
  the server has even heard.
- **Two players on one server can be in different modes.** Loose reach into bags is per
  player too, since it is part of the mode. A magazine handed back or loose rounds
  adopted happen on the player's own next look at the gun, as before.
- **The server config is gone.** The world's `serverconfig/rangedweaponsmod-server.toml`
  from 2.7.x is left where it is and ignored (NeoForge reads only registered configs);
  the box's copy can be deleted or forgotten.
- Gametests set the mode on their own mock player (`loose(gunner(...))`), so the batches
  D-0023 needed for a shared value are gone; the HUD booth chooses through `FeedSync`
  like a client.

Rejected: keeping the server config as an override that forces everyone (not asked; two
sources of truth); a data attachment on the player (a non-persistent attachment is lost
on death and a persistent one would outlive the client's own file); a command to switch
(the config page is the idiom, and the file is there for anyone who prefers it).
