# D-0007 — The automatic class holds; every other class fires once per pull; aiming is a stance

**Decision**: Whether a gun keeps firing while the trigger is held is
decided by its protocol class: `automatic` holds, everything else fires
once per pull and `fire_rate_ticks` is only how soon the next pull may
fire. The trigger's rule table gains one clause -- not automatic and
already fired this press: idle -- placed after the reload and empty-gun
rules so a pull on an empty semi-automatic still reloads. Aiming down the
sights is a fifth stance beside sprinting, moving, crouching and airborne,
with its own multiplier in the handling's `spread` factors, told to the
server by one message on each change; the zoom, the scope's mask and the
hidden hand are the client's alone.

**Why**: Rusty asked for the rest of the lineup to differ in feel, not only
in numbers, and a pistol that sprays like a machine gun does not. The
class was already there, already the thing Armed Pillagers' policy reads,
and the one word in a profile that says what kind of gun this is; a
separate `fire_mode` field would have been a second place for the same
fact. Aiming as a stance keeps spread one function over one record; the
scoped rifle's whole difference on the server is a small `aiming` factor.

**Alternatives rejected**: *A `fire_mode` profile field* — a second axis
that could disagree with the class. *Aiming as a server-side zoom* —
nothing on the server needs it; the message carries one bit.
*A spyglass-style use action for the scope* — it would put the gun "in
use", which the trigger design exists to avoid (D-0002, D-0006).

**Follow-ups**: Mouse sensitivity is not reduced through the scope;
vanilla scales it only for its own spyglass and offers no hook. Rusty may
want it.
